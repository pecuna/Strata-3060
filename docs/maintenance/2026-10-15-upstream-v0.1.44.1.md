## Fork preservation and new findings

Existing SSRF/image-fetch refusal, artifact SHA256 refusal, immutable MTP expected
hashes, pinned-revision refusal, no implicit engine updates on ordinary start,
benchmark private config/log creation and fork-first acquisition remain required.
Three independent reviews separated runtime, installers and native input/loading.

New Mac setup findings were reproduced with mocked/no-GPU fixtures: prepared MTP
reused without the hardened verifier; rerun dropped API key/allowlist/CORS fields;
ordinary start ignored explicit host/key options. All three were corrected with
RED/GREEN regressions. The image job spawn/log-failure cleanup gap was likewise
corrected and regression-tested. Follow-up review found inherited config backups
and predictable config temporaries could expose credentials or follow destination
links: shared writers now use random atomic POSIX-0600 files, destination replace
rather than link following, failure cleanup and Git-ignore rules. Six regressions
cover the config/backup protections. The UI's dynamic network disclosure was also
corrected with a failing-then-passing source regression; it no longer restores the
misleading “Nothing leaves it” claim. Native Mac and Windows ACL behavior were
not exercised.

Optional generated-image URLs deliberately act as bearer capabilities, without
API-key checks or expiry; session snapshots can persist until a later restore.
Do not enable image generation on this deployment without separate policy review.
Existing trusted-client assumptions still include local image paths, configured
MCP/before_load integrations and unbounded HTTP handler/thread concerns. No
firewall, TLS or backend-auth configuration changes are part of this import.
Native malicious-model metadata arithmetic and fallback library search warrant
further hardening; no prompt-controlled route was established with fixed trusted
model artifacts. Do not use this review as permission to load untrusted models.
